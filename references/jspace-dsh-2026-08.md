# J-Space / dsh-router 研究细节与采纳记录

> 记录一次"外部插件评估"的完整过程：两个候选（J-Space Cognition Suite、dsh-routing-suite）的定位对比、安装验证、A/B 实测设计，以及最终采纳结论。
> 评估方法见上层 `SKILL.md` 的"评估流程"。

## 背景

DeepSeek Harness（DSH，命令行 `dsh`）开源后，社区插件数量快速膨胀，"一切皆插件"（Cordis 插件内核）。
待评的两个候选都出自该生态，但**绑定程度完全不同**——这是采纳与否的分水岭。

## 候选一：J-Space Cognition Suite

| 维度 | 内容 |
|---|---|
| 定位 | **模型无关**的推理时控制系统（inference-time control），打包为通用 Skill，可跨平台使用 |
| 依赖 | 无强运行时绑定——不依赖 DSH、不依赖特定模型 |
| 结构 | 单入口 `SKILL.md` + 9 个模块（自省 / 定向聚焦 / 深度推理 / 广播 / 容量 / 自我监控 / 简写 / 标记 / 经验）+ 3 个参考文件 + `scripts/`（纯标准库控制器、`verify_suite.py` 完整性校验、workspace ledger） |
| 门控 | 三档：**fast**（单步可验证，不加载模块）/ **full**（2-4 步有界交付，1-2 模块 + ship 检查）/ **loop**（多阶段多文件跨轮次，ledger + 广播 + 检查点 + 恢复） |
| 输出分层 | 三寄存器：inner（密集思考）/ ledger（状态行：目标 / 核心 / 已验证 / 开放 / 下一步）/ outer（干净输出）——**与"过程不展示、只看结果"的输出偏好天然契合** |
| 审计点 | seam 审计：子任务完成、工具调用前、文件写入前、交付前刷新账本；每第 3 个 seam 刷新 premise |

### 安装与验证记录

1. 浅克隆审查：确认控制脚本纯标准库、无网络调用、只写自身 `.jspace/` 工作目录 → 安全检查通过；
2. 复制到本地 skills 目录；
3. 跑自带 `verify_suite.py` → 输出 clean（one entry / one premise / nine modules / controller anchors aligned / no version talk）；
4. `skill_view` 确认 `readiness_status: available`——**不能只 ls 目录就宣称装好**。

**注意**：校验脚本要求 premise 逐字一致，装后**不要修改其内部文件**，否则完整性校验会挂。

## 候选二：dsh-routing-suite（DSH 专属）

构成：运行时注入器（`dev_*` 工具全家桶）+ 路由预设（含 spec / react / weak 行为带）。

### 核心研究结论

- **persona 轴不是连续可调**：三段结构——spec 稳定带 0-0.19 / 不稳定过渡带 0.2-0.49 / react 稳定带 0.5-1.0；
- **条件选错代价约 10 分**：spec 条件维护任务 99/96，react 条件新建任务 10/10；反选则跌到 91/6；
- **路径承诺**：首轮定轨迹，中途改条件只扰动 1 个推理块；**模型无法自我路由，必须外部路由**；
- **对照组**：换词法 prompt 分数不动 → 路由收益主要对强模型，对轻量模型增量有限；
- 路由能力：首条消息分类 build / fix / weak → 注入稳定带 persona + 首轮核心工具面 → 首次持久工具调用后展开全量目录；near-field 引导（缓存命中 92-94%）；三锚（回顾 + 收敛 + 反跑题）把开放任务完成率从 0% 拉到 100%。

**对 Hermes 唯一可借鉴点**：**首轮工具面收窄**——首轮只暴露核心工具，首次持久调用后再展开全量。

### 勿混淆：整合包

另有一个把 J-Space + 其他 preset + dsh-routing-suite 打在一起的**整合包**（PowerShell 安装脚本，Windows/DSH 向）。
它是组合分发，不是独立插件本体——评估时须查上游链接链回本体，避免把整合包当成"本体功能"来打分。

## A/B 实测设计（验证"装了到底有没有用"）

- **任务**：审计一个包含 5 个 Python 文件（合计约 885 行）的第三方技能目录，输出编号问题清单（文件名 / 行号 / 描述 / 严重程度 / 修复建议），**不改文件**；
- **对照组**：子代理无任何 skill 指示，常规执行；
- **实验组**：子代理先加载目标 skill，再严格按其协议执行（gate 分类 → loop pass + ledger + seam 检查 + ship 验证）；
- **派发方式**：**串行**（禁并发——并发会触发账户级限流，且两组互相污染）；
- **评分维度**：问题数 / 准确性（**父代必须逐条读码抽查验证，子代理自报不可信**）/ 是否实际执行验证动作 / 结构化程度。

**关键坑**：实验组子代理**不会主动加载 skill**，必须在 context 里写明"先加载该 skill 再严格按其协议执行"，否则 A/B 完全失效；
另外，本会话若已加载过目标 skill，"安装前"状态已被污染，对照组必须用隔离子代理跑。

## 结论

| 维度 | J-Space | dsh-routing-suite |
|---|---|---|
| 现在能用 | ✅ 已装、已校验 | ❌ 不部署 DSH 就用不上 |
| 依赖 | 模型无关、无运行时绑定 | 强绑定 DSH 插件系统 |
| 收益 | 与输出偏好契合，推理纪律提升 | 收益主要在强模型，需外部路由配套 |
| 维护成本 | 零（纯标准库、自校验） | 高（跟随 DSH 版本） |

**采纳 J-Space**；dsh-router 不部署 DSH 就不碰，仅吸收"首轮工具面收窄"这一条设计思路。
知识库沉淀：学习笔记 → 飞书文档 + 多维表格（走知识库管道，用户已授权不询问）。

## 避坑清单

- 建飞书文档时 `--content @path` **只接受相对路径**（须 `cd` 到工作目录用 `./xxx.md`，或用 `-` 走 stdin），绝对路径报 `invalid_argument`；
- 多维表格写入用**中文字段名**（文档名称 / 关键词 / 备注 / 创建日期 / 文档链接 / 文档类型 / 标签）；
- 外部 skill 装后不要改其内部文件（完整性校验会逐字比对）；
- 评估结论必须给**对比表 + 明确建议**，不给过程。
